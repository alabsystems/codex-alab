# Bounded publication preparation diagnostics

Decision: let only publication's fresh bare initialization and local candidate
fetch select a closed, fixed Git failure stage. The common Git helper keeps its
default error text and original stdout return for every allowed exit code.
Unknown stage values refuse before starting a subprocess, without rendering the
value. Git argv, sanitized environment, capture behavior and 120-second timeout
are unchanged. Preparation failures remain ordinary `Refused` objects with no
native error metadata and cannot enter the `Advanced` publication-race interface.

For an opted-in disallowed exit, examine only the last 4,096 stderr bytes after
requiring that whole sample to be valid UTF-8. An exact English
`No space left on device` adds only the constant diagnostic
`Git reported no space left on device`. No stderr, argument, path, URL, config,
or process-result object is rendered. Invalid UTF-8, localized or unrelated
text, an out-of-window phrase and a split UTF-8 boundary retain the generic fixed
stage/exit message. This is a Git child text category, not native errno evidence
or proof about volume capacity. `capture_output` still retains the full child
output in memory. No retry, cleanup, locale, threshold or transport policy changes.
