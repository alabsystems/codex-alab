# CX-190 wake mail review

Preserve `sf56dad/CX-190` at `a90afd272f35` for its resolver. It contains
one work-in-progress commit on `3685be8935`. At review, main
`4eda3d99ee` had 417 commits beyond that base. Git computed a clean merge.
The checkpoint would start a native turn from mail sent by the collector
named in the host's `wake_from` policy. Source inspection identified two
issues to resolve before merging. Runtime qualification remains pending.

**Revocation during delivery.** In the checkpoint's `supervisor.rs`,
`wake_turn` captures the sender before awaiting the inbox and body reads.
A supported policy refresh can replace or remove that sender on the same
claim. After another await to persist the busy record, `look_at_wakes`
checks whether the supervisor is acting, whether an upgrade began and
whether the TUI is busy. It can then submit the previously read body under
the changed policy. Bind the body to the collector revision and the
supervisor's admission fence. The existing `start_turn_if_idle` accepts
per-turn extension data. Core invokes `TurnAdmission` after reserving the
idle slot and before consuming input. Recheck both authorities there. A
regression should hold the body read across a sender revocation, including
revocation followed by regrant, and check for zero turns and receipts.

**Expired timer.** In `mail_wake.rs`, `watch_wakes` reconstructs a sleep
from `look_at` each iteration. When the last waiting row disappears,
`consider_wake` returns before clearing that deadline. Once it expires,
the watch can repeatedly select the same elapsed timer. Clear the deadline
through the same serialized path as the other outcomes. Exercise this by
removing the last note while a recheck is armed, advancing the clock, and
observing the watch park again. A queued note behind a dated provider wall
also schedules a separate 60-second recheck. Let the provider's existing
one-shot wake its recovery and revisit the note on the next idle or relevant
state change.
