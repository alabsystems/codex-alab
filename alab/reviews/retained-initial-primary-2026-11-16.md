# Retain the initial request and its actual primary Core

This is a component checkpoint on the live-update qualification branch. The
ordinary retained target remains inactive; this does not deliver a complete
update handoff or select an installed application.

The SDK carries the actual physically received attachment in a private shared
receipt. Admission asks the original Native controller for its exact current

authentication, counter and I/O uncertainty after dispatch still closes it, as
does failure to decode the exact origin response. Ordinary transport calls keep
their previous close-on-error policy; there is no reconnect fallback.

its original permits, policy and request context remain held. The backend keeps
the immutable whole operation, captures the exact returned Core before fallible
publication, and can bind the actual allocated checkout supplied in its plan.
Reconnect observers need a fresh current origin and the original selection.
They attach to the same Core through the original serialized listener path.
Unknown entry outcomes remain sticky and prevent a successful drain instead of
repeating construction.

and exact-current/pending-unload checks. It inhibits ordinary idle unloading of
that same Core while the backend owns it. No client subscriber, task-child
keepalive or replacement unload deadline is created. The last owner wakes the
original eligibility logic, and a weak slot prevents an ownership cycle.

Typed response metadata wraps the actual protocol payload and preserves typed
analytics. Serialization retains other metadata owners and refuses namespace
collisions. Metadata-only acknowledgment has no synthetic upstream response or
arbitrary raw-result constructor.

Unused TUI checkout-binding hooks are deferred until their real producer and
consumer are mounted together. The backend binding resource and initial plan
remain available. Normal full offline metadata resolution added only the two
