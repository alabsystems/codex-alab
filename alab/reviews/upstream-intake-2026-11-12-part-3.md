## Required adaptation before qualification

`d0edb0b1` moves the exact composer allocation and status-rendering code that ALab extends. Preserve upstream's `FooterLayout`, `StatusLine`, structured passive status capture, dimming, and hyperlink suppression. Reapply ALab's height/render hooks at the current composer entry points; rebase the footer-cap hook onto the new per-composer allocator. Do not resurrect `native_status.rs`, the old cache fields, or the removed single-line passive renderer. Do not put the active ALab goal/account cap in the shared `FooterLayout::new`: passive side panes also call it, and a focused thread's global ALab state must not change another pane's budget.

The intended behavior remains:

- Enhanced, focused composer: a goal and account get separate rows when the native remaining budget permits, while draft cursor, account click target, and interactive hints keep priority.
- Enhanced, unfocused composer: retain the existing ALab presentation decision within the native budget; no active-thread data is imported into a different passive conversation.
- ALab off/vanilla: use upstream native multiline wrapping and passive dimming unchanged.

The actual merge preview reports `composer_layout.rs` and `status_surface.rs` conflicts, matching this assessment. These are the required ALab code adaptations in this part. No ALab-owned call to the removed `Config::set_legacy_sandbox_policy` or constructor/pattern match on the removed `FooterContent::Line` was found.

## Activation and custody decisions

The source-V1 activation hold remains in force. None of these decisions enables it or treats upstream MCP refresh, response-ID allocation, recovery liveness, or permission-profile changes as equivalent to ALab's native source/cross-account handoff contract.

Keep `analytics.enabled=false`, `otel.metrics_exporter="none"`, `features.plugins=false`, and the existing no-recommendations policy. The new OTLP helper is accepted only as an explicit configured HTTP-exporter capability. It must remain unset by default; repository configuration must not launch it, admin-controlled exporters must not receive user helper headers, and an ineligible exporter set must create no worker. The new reasoning-removal metrics are bounded metadata, not content, and must not enable an exporter.
