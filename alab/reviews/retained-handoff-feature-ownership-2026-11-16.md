ownership and cancellation. Retained frontend replacement is another mechanism
for that semantic responsibility, not a new build/adoption or storage-recovery
feature. Its source Goal Hold/inhibitor is not an acknowledged persistence hold.
`history-pagination` continues to own page slicing/grouping; the actual writer
incarnation, inherited cutoff and live listener continuity belong here.
`account-isolation` owns credential-reader provenance and retirement even when
only account/configuration DATA is delivered to the frontend.

Add the actual owned implementation entry points outside the already-listed
`alab-core/glue` directory: Native backend startup/owner, retained Goal gate,

under account isolation. Every new implementation path exists in committed
`cb670`; outside/untracked UI drafts do not satisfy this validation.

## Scoped contracts, not successful scenarios

The former universal Native End/persistence-closure invariant is explicitly
scoped to runtime/tree transfer. Retained frontend replacement keeps its actual
backend alive and preserves each existing Core/writer incarnation. A genuine
empty selected slot is valid and does not assert that no Core exists or invent
a primary. Initial birth/Go/current A/F1 remain separate from actual replay,
UI/input and replacement App promotion/commit. Configured NoPrimary carries the
same closed hold; first/later source-bearing candidates require S1/S2, while
generic R reconciles only an actual Selected owner. Accepted work is not canceled
merely to reach an idle-only checkpoint.

The new retained contracts also require exact listener/history/callback/reader
custody and current physical-tenure capability semantics: false or unavailable
current capability must not inherit a historical positive. Capability DATA
provides no Native/model grant. Account/policy/loader reads are successive
original backend observations, not an atomic config version. Fresh reader
admission must recheck actual stopped/withdrawn Input after the Native await;
already accepted work retains its original cleanup ownership.

The catalog remains 14 semantic features and accounts for all 100 hook topics.
It adds five REQUIRED scenarios (82 to 87). **All five are UNRUN and UNQUALIFIED
at the full retained UI/Native scope.** Their text is a contract, not runtime
or parity evidence. Passing this ownership check cannot pass final coverage.

Required gaps include a real independently signed Native/Source/UI pair for
initial birth and replacement Go, repeated fresh A/F1/App rebind and reconnect;
pre-UI H1 and NoPrimary-to-real-Core hold continuity; exact selected/Main/Side
S1/S2 versus R release; actual original replay/draw/input and complete pending
view/editor continuation; captured Source callback outcomes plus semantic ACK
and unconfirmed human-response custody; actual C2 reader/cloud routing and
joined old reader/unused-seed retirement; and accepted worker/lease/slot/Hold
cancellation and shutdown overlap. Lower parser/data/scheduling/component
controls do not prove those conjunctions. Native constructor/Go/App authority,
Source endpoint closure, UI application and Core/effect completion stay distinct.
The ordinary selector, production activation, full certified application gate,
main landing and installation remain separately unqualified.

The future unmounted `retained-ui` topic belongs to the same semantic family,
but is deliberately not added as an already-mounted topic here. Its exact
committed hooks and implementation/coverage must be reviewed with that component.
