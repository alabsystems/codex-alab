# Preserve completed source observations after later failures

A tiny local Git repository with two disconnected roots resolves both requested
commit identities, but merge-base exits 1. The previous report API propagated
that command error, and its CLI returned 1 with no JSON. A separate valid Git
commit with committer timestamp 253402300800 (year 10000) exposed the same loss:
Python cannot convert that timestamp, so already read source/frontier/pending
observations disappeared from the CLI output.

Decision: treat ref resolution and the ordered frontier, pending-commit and
pending-timestamp reads as observations. Expected I/O, command and conversion
failures become structured errors while previously established fields survive.
Fields that were not established remain unknown; failed ancestry does not
become zero lag. An error still makes the CLI exit 1. The existing ambiguous
frontier refusal remains. KeyboardInterrupt and SystemExit are outside these
exception boundaries. Optional artifact/qualification fields remain independent;
no native gate, fetch, adoption or proof is inferred by this local report.

The source-only deep-JSON recursion hypothesis was withdrawn after the managed
CPython 3.14.8 decoder parsed every tested depth through 30000 (60081 bytes).
That bounded experiment does not establish a parser failure or justify a patch;
no artifact parser change is included.

Independent static review approved the frozen implementation and eight new
controls; the prior 16 test methods and their existing helpers are unchanged.
The same 24-method module runs from coherent exact baseline
`2b895cac26a0d6a9894ebd24997fd4d2d12ace4f` and fixed source, with identical
final tests. Baseline: actual exit 1, two assertion failures and seven error
events across six failed parent methods (18 methods fully pass). Fixed: actual
exit 0, all 24 pass, zero errors or skips. Controls use real disconnected roots,
a real year-10000 commit, actual CLI subprocesses, a real crisscross graph,
and module-local Git command fault injection. Cancellation identity survives.
Only upstream_status.py differs between the two selected source bundles.

The private counterfactual driver itself exits 1 after retaining both test
results: its final inventory also counted four generated bytecode files per
bundle as inputs. Its original code/context are retained. A separate seal and
root verification check every original input hash and identify only those
new generated outputs; no test run or exit was relabeled or repeated.
