# Compose the reviewed forty-commit range

Use the supported sync with exact target
`ce3031018ef130e653ed4d9c5bb971652de97161` over intake-bearing main
`647751d5cdd6aa1861b53e181522e2adf8dcbd56`. The full range is reviewed before
integration. A single batch keeps the required cross-commit adaptations and
their exact-source scenario evidence together. Main history is neither rebased
nor force-pushed.

The sync reapplies the existing removed-path policy. The plugin test conflict
retains ALab's recommendation-policy module and upstream's removal of the old
force-reinstall import. Both compressed protocol exports are regenerated by
the actual Rust schema writer; selecting upstream's archives during conflict
resolution is only a temporary input to that writer.

The private memory test now exercises an actually captured retained assistant
revision, including allocation metadata, and proves replay does not allocate a
replacement revision. Compaction retains a nondefault next-item ordinal. The
existing tree-capture regression includes an active grandchild and proves the
whole captured tree stops while a foreign tree continues.

Upstream's immediate WebSocket size fallback keeps the existing ALab provider
deadline and typed status hooks. A new focused regression covers the early
fallback before retry exhaustion. Its diagnostic no longer incorrectly claims
that every HTTP fallback exhausted the retry budget.

Cloud idle recovery retains a non-counting observer of the original source and
sticky application revocation. Each polled recovery episode acquires its own
source-use permit from that frozen policy, including credential checking and
Attach. Completion or cancellation releases the episode; an idle cached owner
cannot prevent retirement. Revoke-then-allow and equal visible token/account
values cannot make a retired source current. The upstream attempt count and
eight-second deadline stay with its recovery state machine.

The new reconnect event is explicit in ALab's backend and upgrade dispatch.
It does not invent a turn, restore a cleared goal, or acknowledge completion.
Parked backend handling preserves both upstream discovery invalidation and
ALab's account/turn ownership and overflow order.

The composer adaptation uses upstream's FooterLayout and structured status
rendering. ALab's goal/account cap belongs only to the composer entry point;
passive side panes retain their own native budgets. Old native-status caches
and rendering types are not restored.

Additional provider scenarios exercise active invalid compaction, an account
switch during pending reset redemption, and queued safety recovery losing
authority before dispatch. These extend validation of existing contracts; they
do not enable new automatic recovery modes.

Native preparation uses the signed Trust 15698 selection, the private Cargo
home, the existing protected profile and explicit unverified compilation. The
initial offline resolver found a cold registry archive cache; preparation then
downloaded the exact locked public dependencies for source and pristine trees.
The pre-existing exact-version allocative vendor substitution remains the only
exception to upstream sourced dependency identities. No compiler override or
containment exception is introduced.

This decision record is committed before qualification. Source-bound scenario
records, actual statuses and full gate output are retained outside the source
tree so recording results cannot change the candidate they describe. Failed or
incomplete checks remain failures until a later exact-source run passes. No
installed binary, account assignment, credential, telemetry default or Source
V1 activation changes as part of this integration.

## Explicit V8 lease release

The next complete ALab run passed the Cargo-copy case among 2,075 test passes,
but the V8 cache fixture returned `WouldBlock` from a lease acquisition. That
log did not identify which acquisition failed. A separate bounded OS diagnostic
proved a real lock-lifetime defect: even a close-on-exec descriptor is inherited
between fork and exec, so closing only the parent's `File` can leave its flock
held by a still-running child.

A private lease guard now explicitly unlocks before closing and retries an
interrupted unlock. The guard is installed immediately after acquisition, before
any later fallible operation. It retains the existing lifetime through native
compiler-group drain and final input checks. A busy owner is still refused;
there is no lock bypass, early release or cache-policy exception.

A deterministic native regression holds the inherited descriptor in a bounded
child, proves `WouldBlock` while the owner lives, then reacquires through the
real cache resolver after owner drop while the child remains alive. Disabling
only explicit unlock makes that exact test fail with `WouldBlock`; restoring it
passes all three V8 tests. Both paths reap their child. Independent source review
found no blocker. This establishes the defect and fix without claiming the older
gate log proves its precise cause. A new source-bound evidence bundle and the
complete native gate remain required before publication.

## Withdraw child-controlled pristine exceptions

Concurrent main added a persistent pristine-failure cache in `6d39f5397a`.
Its exception store was beneath the private Cargo home, which contained build
scripts and tests may write. Public key hashes and file ownership cannot prove
which same-user process created a record. The key also omitted private Cargo
configuration that can change runtime behavior, including certificate inputs.
A cached failed-test answer could therefore excuse a candidate failure without
a trustworthy equivalent upstream execution.

Withdraw the complete reuse feature and retain actual pristine comparisons.
The cache commands, module, gate integration and their documentation are removed;
existing cache data is left alone. A future design needs storage and observations
owned by an outer trusted controller and a complete execution-boundary key.
The independently reviewed frozen release-baseline change in `b2b4bdd013` and the
path wording correction in `ce7813fda2` remain intact.

A gate regression supplies the old path's compiler-key prerequisites and a
candidate-controlled reader returning a fabricated failed-test match. The safe
gate still executes pristine and rejects the candidate; an isolated copy using
the old cache-enabled gate instead accepts the fake hit without running pristine,
causing the regression's expected failure. All 131 distinct gate, result and
version Python tests passed, and the complete native release package passed
14 tests with its two existing ignored cases. No persistent exception store is
trusted by the resulting gate. Fresh exact-source evidence and the complete gate
are still required before publication.
